## Décisions

1. **Verrou simulé** : `db.lockBusy?: boolean`, sur le modèle de `db.mailError` (état serveur modifiable en cours de test, ou semé par `fakeScriptOptions`). Tant qu'il vaut `true`, toute action POST sauf `getAdminState` et `checkPassword` répond « Le serveur est très sollicité : réessayez dans quelques secondes. » **tout de suite** (le script attend 20 s). Ordre de Code.gs : lecture du corps (erreur de `JSON.parse`, corps `null`), puis verrou, puis action inconnue et mot de passe ; une action inconnue reçoit donc le message du verrou. `failNext('error')` garde son rôle (une requête, n'importe laquelle, lecture comprise).
2. **Comparaisons de Code.gs reproduites** : `updateRowByKey` et `removeRowsByValue` comparent en chaînes (`sameCell`) ; les `find(… === …)` restent stricts (réservation à modifier, jour d'une réservation, plats existants d'`addDayR2`). Seul écart : `editBookingR1` / `editBookingR2` modifient la ligne trouvée par la comparaison stricte, alors que Code.gs réécrit la première ligne dont l'`ID` est égal en chaîne ; les deux ne diffèrent que si deux lignes ont des `ID` égaux en chaîne et de types différents.
3. **Corps mal formé d'`addDayR2`** : `items` non tableau ou ligne `null` donnent les messages de V8 (« (items || []).filter is not a function », « Cannot read properties of null (reading 'name') ») ; le jour est déjà écrit, aucun plat ne l'est, comme dans Code.gs.
4. **`setConfigField`** : `config` reste un objet clé → valeur ; une clé `undefined` ou `null` crée la clé vide (cellule vide de Code.gs). Aucune liste blanche (b-10).
5. **E-mails d'annulation** de `deleteBookingR1` / `deleteBookingR2` non simulés : leur statut n'est jamais renvoyé (02 § 6.2) et le site ne peut pas les observer ; `db.mailError` ne touche que les confirmations.
6. **Jeu de base inchangé** : il contient déjà les réservations nominatives du lendemain (R1 : Ungerer avec détail et observation, Martin, Petit aux compteurs vides ; R2 : Gsell à 3 Bowl, Bernard, Durand orpheline), donc I-03, I-04 et C-13 ont leurs données. Le garder tel quel évite de changer les comptes que P3 (0) peut déjà lire.
7. **Aides de test** `postStaff` et `rowsOf` ajoutées à `src/test/fake-script-server.ts` (aides des tests du faux script, fichier de P1 (a1)).
