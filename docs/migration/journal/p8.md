## Décisions

1. **Branches `legacy` des scénarios gardées.** Elles écrivent la variante de l'ancien site de chaque `@changed:E-xx` ; `changedTagsMatchPlanGaps` compare toujours les étiquettes au § 4.2. Les retirer toucherait une vingtaine de fichiers de scénarios sans changer une assertion `react` et compliquerait le rebase si la validation produit des correctifs. `e2e/pages/target.ts` rend `"react"` pour tout projet autre que `legacy`.
2. **Projet `production` dans sa propre configuration.** Dans `playwright.config.ts`, `pnpm test:e2e` sans `--project` lançait aussi le projet `production` contre le vrai site, et démarrait les serveurs locaux pour rien. `playwright.production.config.ts` n'a ni `webServer` ni faux script ; la configuration par défaut ne connaît plus ce fichier (`react-only` l'ignore toujours).
3. **Test du formulaire qui échoue sans jour réservable** plutôt qu'un `test.skip` (interdit) ou un succès silencieux : le message renvoie à une vérification à la main (`bascule.md` 4.6).
4. **`workflow_dispatch` sur `main` pour `deploy`** : republier après un changement de la variable de dépôt ou au retour d'un retour arrière, sans commit vide. L'environnement `github-pages` limité à `main` refuse toute autre ref une seconde fois.
5. **Commentaires de provenance** : `legacy/app.css` devient `v1-final:app.css`, chemin de l'ancien site dans le tag (`main` a ces fichiers à la racine : `git ls-tree main`), lisible par `git show v1-final:app.css`. Convention notée dans `CLAUDE.md`.
6. **Tests dorés de la copie locale** : les cas « l'ancien `loadCache` lit la copie du nouveau code » et « le nouveau code lit `saveCache` » ne se figent pas sans l'ancien code. Restent : l'exemple de `03` § 1.1 relu et réécrit champ pour champ (`local-cache-v1.json`), la copie sans etag d'une session collègue, les copies gardées ou ignorées. Le retour arrière dépend de ce format (R-21).
7. **Retour arrière, première façon** : ajout d'une règle `rollback` dans l'environnement `github-pages`, qui n'autorise que `main` après l'étape 3.2 ; le PLAN § 7 ne la mentionne pas. Non vérifié sur GitHub (aucun accès depuis la session) : la répétition à blanc le confirmera.
